# 全局请求错误中文 Toast 设计

## 背景

当前请求失败时，页面可能直接展示 Axios 的英文默认错误，例如 `Request failed with status code 502`。错误展示分散在登录页、系统用户页和路由守卫中，React Query 重试还可能造成重复提示。

## 目标

- 所有 HTTP、网络、超时和后端业务失败统一进入全局中文 Toast。
- 页面保留必要的失败状态和重试入口，但不再重复展示具体错误文案。
- 对短时间内相同错误去重，避免查询重试连续弹出多个 Toast。
- 不新增 UI 运行时依赖，不改变现有登录失效跳转行为。

## 方案

请求层通过一个与 React 解耦的错误通知通道发布标准化错误事件。Axios 响应拦截器处理 HTTP、网络和超时错误；`requireApiData` 处理 HTTP 200 但业务码失败的响应。应用根部挂载全局 Toast 宿主，订阅错误事件并负责自动关闭、去重和展示。

错误文案优先使用后端返回的明确业务消息；没有可用业务消息时按错误类型使用中文兜底：401 为“登录状态已失效，请重新登录”，403 为“没有权限执行此操作”，404 为“请求的资源不存在”，408/超时为“请求超时，请稍后重试”，429 为“请求过于频繁，请稍后重试”，5xx 为“服务暂时不可用，请稍后重试”，其他网络错误为“网络异常，请检查连接后重试”，未知错误为“请求失败，请稍后重试”。

全局 Toast 使用现有 `Toast` 组件和 `danger` 语义，固定在顶部居中位置，显示约 4 秒，并以错误类型和文案作为短时间去重依据。

## 影响范围

- `src/services/http.ts`：发布 Axios 请求错误。
- `src/services/api.ts`：统一错误文案，并发布后端业务失败。
- `src/ui`：提供全局 Toast 宿主所需的订阅能力或组合组件。
- `src/App.tsx`：挂载全局 Toast 宿主。
- 登录页、系统用户页和路由守卫：移除具体错误文案的重复渲染，保留状态和重试/退出操作。
- `docs/architecture.md` 与 `docs/ui-system.md`：记录请求错误流和 Toast 交互约定。

## 验证

- 静态检查错误文案不再泄漏 `Request failed with status code`。
- `npm run lint` 和 `npm run build` 通过。
- 在桌面开发环境验证 401、502、网络错误和业务码失败均显示中文全局 Toast，查询重试不会连续重复弹出。
