# 演示数据导入

先创建空的 `web_project` 数据库并启动一次后端，让 Flyway 自动创建业务表和默认配置；**不要再导入仓库根目录的 `web_project.sql`**。确认应用已成功启动后，再运行 `import_demo_data.bat`，它只向已有表插入 50 个系统用户和 100 个普通用户，最后运行 `03_verify.sql` 显示统计结果。

在后端仓库目录的 PowerShell 中执行：

```powershell
$env:MYSQL_BIN = 'E:\kaifa\MySQL\MySQL Server 8.0\bin\mysql.exe' # 改为本机路径
.\demosql\import_demo_data.bat
```

MySQL 客户端已加入 `PATH` 时可省略 `MYSQL_BIN`。查找顺序为 `MYSQL_BIN`、`PATH`，最后检查脚本列出的常见安装目录。脚本为 UTF-8 编码，执行时切换为 UTF-8 代码页。

连接参数支持环境变量 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`；默认连接本机 3306 端口的 `web_project`，账号密码沿用应用的本地开发默认值。脚本不解析 `application.yml` 或 `DB_URL`，连接其他数据库时需单独设置这些参数。

只在本地演示库运行。两份 SQL 都是纯插入，重复执行会触发唯一键冲突，不会删除或覆盖已有账号。若系统用户已导入、普通用户导入失败，修正错误后单独执行 `02_user_account.sql`，避免重复插入第一批数据。MySQL 的连接、导入或校验错误会显示在终端，并以非零退出码结束；只有三步全部成功才显示 `[DONE]`。

回归验证使用临时独立数据库，测试账号需具有建库和删库权限，结束后只清理测试自身创建的库：

```powershell
$env:MYSQL_BIN = 'E:\kaifa\MySQL\MySQL Server 8.0\bin\mysql.exe' # 改为本机路径
python -X utf8 scripts/test_demo_import.py
```
