# 存储数据库设计

结构与初始配置由 `web_project.sql` 定义，不提供迁移脚本。已接入全局配置、OSS 空间管理和系统用户头像服务，支持本地存储和阿里云 OSS，缩略图、水印不在本期范围。

## 配置与表结构

复用 `sys_config`，`config_value` 保持 `VARCHAR(255)`：

| 配置键 | 初始值 | 含义 |
| --- | --- | --- |
| `storage.type` | `local` | 后续新上传使用的存储方式，取值 `local`、`aliyun` |
| `storage.aliyun.access-key-id` | 空字符串 | 全局 OSS AccessKeyId，空值表示未配置 |
| `storage.aliyun.access-key-secret` | 空字符串 | 全局 OSS AccessKeySecret 的加密密文，空值表示未配置 |
| `storage.aliyun.default-space-id` | 空字符串 | 默认 `storage_space.id` 的十进制字符串，空值表示未选择 |

本地根目录继续使用部署配置 `UPLOAD_DIR`，不写入数据库。凭据采用 AES-256-GCM，密钥由 `STORAGE_ENCRYPTION_KEY` 环境变量提供（Base64编码32字节）。每次加密生成12字节随机nonce，nonce与含128位认证标签的密文拼接后Base64编码；输入限定最多128个可见ASCII字符，编码长度不超过255字符。配置查询只返回是否配置，不返回 AccessKeyId 或 Secret，数据库不写加密密钥。

`storage_space` 只绑定现有 OSS Bucket：保存 Bucket 名称、真实 Region ID、可选 HTTPS 访问域名和时间。Bucket 名称以唯一索引防重复，Region 保存 `oss-cn-hangzhou` 这种真实标识，不保存国家、地区分栏。访问域名包含 `https://`，不包含 Object Key、查询参数或末尾斜杠；为空时由 Bucket 和 Region 生成默认公网域名。域名用于公开访问，不作为 OSS SDK 的任意请求地址。

表中不保存默认标记、启用状态或 AccessKey；默认空间只有上述一个配置项。Bucket ACL 以云端实际结果为准，不在绑定表维护第二份权限状态；头像空间仅允许公共读（PublicRead）；PublicReadWrite 会被配置 API、OSS 实际 ACL 校验和空间同步拒绝。绑定时核对所选权限与实际 ACL 一致，由后端 AccessKey 凭据上传；不自动修改云端 ACL。Private 暂不支持，因为现有读取路径会直接跳转到公开 OSS URL，没有签名 URL 授权机制。

`storage_file` 保存文件 ID、实际 provider、空间 ID、存储路径、MIME 类型、字节大小及时间。本地文件的 `space_id` 为空，路径相对 `UPLOAD_DIR`；OSS 文件必须有 `space_id`，路径为 Object Key。数据库 CHECK 约束 provider 与空间空值的组合，并限制路径为 1～1023 个 UTF-8 字节。路径区分大小写，不对长 Object Key 建立前缀唯一索引；后续上传生成独立路径。`space_id` 索引用于删除绑定前查询文件引用。

`sys_user.avatar` 改为可空的 `avatar_file_id BIGINT`，关联 `storage_file.id`，引用查询有对应索引。系统用户、空间、文件 ID 均使用有符号 BIGINT，Java 对应 Long。普通用户 `user_account.avatar` 仍用于现有个人资料接口提交的头像 URL，不接入普通用户上传。

## 业务接入约束

实现遵循以下规则：

- 切换全局存储方式只影响新上传，读取、删除旧文件必须使用其记录中的 provider、空间和路径。
- 切换到阿里云前检查凭据与默认空间有效；默认空间 ID 必须指向已绑定空间。
- 同步空间时分页查询账户实际 Bucket，先逐个检查云端 Bucket ACL；只要有不符合 PublicRead 的 Bucket 就拒绝整次同步且不写数据库。Bucket 的 Region 以阿里云结果为准，有文件引用的目的地不允许改变地域。
- 默认空间和仍有文件引用的空间禁止删除；删除绑定不删除云端 Bucket。空间关联由 Service 保证，不引入外键、触发器或存储过程。
- 本地路径必须处于 `UPLOAD_DIR` 内；域名、MIME 类型和 OSS Key 的真实限制在上传与配置入口校验。
- 文件写入与远程调用放在短数据库事务之外；数据库写入失败后清理新文件，头像引用提交后再清理旧文件。清理失败保留原始异常并附加清理异常；物理删除失败保留文件元数据。
- 系统用户接口输出的 `avatar` 由文件 ID 生成 `/files/{id}` 访问地址，本地文件返回图片字节，OSS文件重定向公开HTTPS地址。

## 当前接入状态

`SysUser`、`SysUserMapper.xml` 与头像服务均使用文件 ID；系统用户登录及列表不再查询旧 `avatar` 列。前端存储配置和空间管理调用真实管理接口。添加空间时在同一表单填写凭据、空间名称和区域；已配置凭据时可以留空沿用，也保留独立配置入口。填写新凭据会先更新所有空间共用的配置，再绑定空间。当前实现接口见 [api.md](api.md)，验证结果另行记录，代码实现不代表云端凭据与Bucket已经完成现场验收。

## 生产 Bucket 安全审计（上线前必做）

1. 打开阿里云 OSS 控制台，对所有已绑定和计划绑定的 Bucket 逐个检查 **Bucket ACL**。头像等公开图片空间应使用 **公共读（PublicRead）**，绝不能使用 **公共读写（PublicReadWrite）**。如果已有 Bucket 是公共读写，必须先在阿里云控制台修正 ACL，再回到 Atlas 绑定、同步或设为默认空间；**本次代码修改不会自动修改实际 Bucket ACL**。
2. 继续检查 **Bucket Policy**、跨账号授权、RAM 权限与历史临时授权，确保不存在允许匿名主体（例如 `Principal: *`）执行 `oss:PutObject`、`oss:DeleteObject`、`oss:PutObjectAcl` 等写操作的规则。**即使 Bucket ACL 显示 PublicRead，过宽的 Bucket Policy 仍可能导致匿名可写**。
3. 后端使用最小权限 RAM 身份和服务器侧 AccessKey 上传、删除对象，仅授权必要的 Bucket 和对象路径，不在浏览器泄露 AccessKey。不要以 OSS 公共读写作为上传授权手段。
4. 若存储身份证件、合同、私人文件等敏感资料，应改成 Private Bucket 并增加短时签名 URL 或后端授权读取；当前 Atlas 的公开头像路径**不支持** Private Bucket，不能直接切换后期待其正常显示。
5. 此仓库当前没有连接生产阿里云账号的权限，不能代替运维人员验证 Bucket ACL/Policy 的真实状态；上线前须完成实际云端审计并记录结果。修改代码**无法撤销以前已经授予匿名用户的写入权限**。
