## 覆盖率

统计整个后端生产 class 的可分析代码，合并 JUnit 和实际 HTTP 执行数据；没有人为排除业务代码，JaCoCo 默认过滤部分编译器/Lombok 生成代码。

- 行覆盖率：**97.47%**（771/791）。
- 分支覆盖率：**88.40%**（221/250）。
- 63 个可分析生产 class 均执行到；接口等无可执行内容不计为 class 覆盖率分母。

布局合并使可分析行数由上一轮的 801 行变为 791 行；未覆盖行仍为 20，分支统计相同，可执行 token 没有变化。行覆盖率的小幅变化不表示业务验证减少。

仍未覆盖的 20 行主要包括：缺失/畸形的已签名 JWT claim 与内部 null 输入防护、换绑旧目标不属当前账号/账号已消失的部分发送分支、全局异常处理的备用 BindException 与缺少字段错误回退、未被业务调用的 `Result.error(String)`，以及唯一索引分类的一个组合条件。明细见 JaCoCo XML/HTML。对应正常业务状态、实际依赖故障和本次列明的关键流程已验证；这些未执行路径仍如实保留，不通过删代码、排除项或弱断言制造 100%。

## 本机性能基线

目标在运行前确定：20 次预热，1、8、24 个并发工作线程，每阶段 10 秒，操作约 40% 资料查询、40% Refresh、20% BCrypt 密码登录。通过标准为零非预期错误，阶段后资料查询返回 HTTP 200。没有生产响应时间 SLA。

| 并发 | 请求数 | 实际秒数 | 请求/秒 | P95 ms | P99 ms | 非预期错误 |
|------|--------|----------|---------|--------|--------|------------|
| 1 | 432 | 10.01 | 43.14 | 58.46 | 67.89 | 0 |
| 8 | 4232 | 10.15 | 416.95 | 65.34 | 81.18 | 0 |
| 24 | 1404 | 10.30 | 136.29 | 906.25 | 972.44 | 0 |

| 并发 | Java CPU 秒 | 结束时工作集 MiB | Redis 内存 MiB | MySQL 连接数 |
|------|-------------|-----------------|----------------|--------------|
| 1 | 7.06 | 481.23 | 0.96 | 11 |
| 8 | 55.66 | 690.41 | 1.12 | 11 |
| 24 | 148.59 | 690.79 | 1.18 | 11 |

本机有 24 个逻辑 CPU；CPU 秒是多核累计时间，工作集和存储指标是阶段结束采样，未宣称测得峰值。应用挂载 JaCoCo，指标包含覆盖率采集开销；MySQL 为已有本机服务，结果受 JIT、开发机资源竞争等影响。最终 24 并发的吞吐量明显低于 8 并发，P95 增长至 906.25 ms；零错误与恢复探针符合本机基线标准，但不能据此承诺生产容量，也没有确定该延迟增长的具体原因。

本次按用户确认的本机短时基线验收，不执行生产 SLA、长时间浸泡或超载极限测试。真实短信/邮件供应商未接入，开发发送实现的验证不代表送达；普通用户前端与浏览器点击验收不在此次后端任务范围。
